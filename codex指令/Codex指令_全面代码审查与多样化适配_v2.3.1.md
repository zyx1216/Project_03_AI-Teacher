## 第一部分：全面代码审查

### 1.1 语法与导入检查
- [ ] 所有Python文件通过py_compile
- [ ] 所有import都能正确解析，无循环导入
- [ ] 无未使用的导入（可选清理）
- [ ] 无硬编码的绝对路径（除项目根目录相关）

### 1.2 异常处理检查
逐个检查以下场景是否有try-except保护：
- [ ] 文件读取（PDF、Word、Excel、图片、JSON）
- [ ] 数据库操作（查询、插入、更新、删除）
- [ ] LLM API调用（超时、网络错误、返回格式错误）
- [ ] OCR识别（图片损坏、识别失败）
- [ ] 数据转换（字符串转数字、日期解析）
- [ ] 图表生成（空数据、数据格式错误）
- [ ] 文件导出（Word、PDF、Excel、ZIP）
- [ ] 外部库调用（pandas、plotly、PIL等）

### 1.3 空数据与边界条件检查
逐个功能测试以下边界情况：
- [ ] 学生表为空时，各功能是否正常（不报错、有友好提示）
- [ ] 考试表为空时，成绩分析是否正常
- [ ] 成绩表为空时，图表是否正常（不报错、显示"暂无数据"）
- [ ] 题库为空时，出题/组卷是否正常
- [ ] 作业表为空时，作业管理是否正常
- [ ] 单条数据时，图表是否正常渲染
- [ ] 大量数据时（1000+学生、100+考试），性能是否可接受
- [ ] 分数为0、满分、负数、空值时，计算是否正确
- [ ] 日期为空、格式错误时，是否有处理

### 1.4 数据一致性检查
- [ ] 删除学生时，关联的成绩、作业是否处理（级联删除或提示）
- [ ] 删除考试时，关联的成绩是否处理
- [ ] 删除题目时，关联的作业题目是否处理
- [ ] 修改班级名时，学生表的班级字段是否同步
- [ ] 导入数据时，重复数据是否去重或提示
- [ ] 事务一致性：多步操作失败时是否回滚

### 1.5 安全检查
- [ ] SQL注入：所有查询使用参数化，无字符串拼接SQL
- [ ] XSS：用户输入渲染到页面时是否转义
- [ ] 文件上传：是否校验文件类型、大小
- [ ] 路径遍历：文件操作是否限制在项目目录内
- [ ] 敏感信息：API Key、密码是否明文存储或输出到日志

## 第二部分：多样化适配验证

### 2.1 学生数据Excel导入适配
测试以下各种列标题格式，确认都能正确识别：

| 场景 | 列标题示例 | 预期行为 |
|------|-----------|----------|
| 标准格式 | 姓名、性别、班级、学号 | 正常导入 |
| 同义词 | 名字/学生姓名、男/女/性别、班别/班级 | 能识别 |
| 英文 | name、gender、class、student_id | 能识别 |
| 带空格 | " 姓名 "、"姓 名" | 能识别（去空格） |
| 多余列 | 姓名、性别、班级、年龄、备注 | 忽略多余列 |
| 缺少列 | 只有姓名、班级（无性别、学号） | 能导入，缺省值处理 |
| 列顺序不同 | 班级、姓名、性别 | 按列名匹配，不按顺序 |
| 班级格式 | "高一1班"、"高一(1)班"、"1班"、"一班" | 统一格式或保留原样 |
| 性别格式 | "男/女"、"M/F"、"1/0"、"男生/女生" | 能识别转换 |
| 空行 | Excel中有空行 | 跳过空行 |
| 重复学生 | 同名同班级 | 提示重复或更新 |

## 第三部分：具体修复要求

### 3.1 必须修复的问题类型
1. **任何导致崩溃的bug**（报错、白屏、500错误）
2. **数据计算错误**（平均分、排名、得分率等）
3. **导入失败**（合理格式的数据无法导入）
4. **图表渲染失败**（空数据、异常数据导致报错）
5. **中文显示问题**（乱码、方框、字体缺失）
6. **文件导出失败**（Word、PDF、Excel导出报错）

### 3.2 优化改进（非必须，但建议）
1. 错误提示更友好（不说"内部错误"，说具体原因和解决建议）
2. 导入失败时，指出具体哪一行哪一列有问题
3. 空数据时显示引导提示，而不是空白
4. 长操作（AI生成、OCR）有进度提示

### 3.3 不做的事情
- ❌ 不新增功能
- ❌ 不改变现有UI布局
- ❌ 不重构代码结构
- ❌ 不升级依赖版本
- ❌ 不修改数据库表结构（除非修复bug必须）
